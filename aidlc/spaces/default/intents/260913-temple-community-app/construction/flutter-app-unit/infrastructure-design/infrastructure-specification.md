# Infrastructure Specification — flutter-app-unit

This Unit owns no AWS resource of its own (NFR Design's `logical-components.md`): every backend resource its six `services/*.dart` files call — Cognito, AppSync, DynamoDB, S3, the reminder Lambdas — is provisioned by the owning backend Unit's own Infrastructure Design. What this document provisions is the **mobile-app side** of infrastructure: how the one Flutter binary is pointed at its backend, the Firebase project behind Crashlytics (and, per reminder-unit, FCM push), the store accounts and signing material a release needs, and the config artifacts that tie them together. The component topology comes from `components.md` (Domain Design), the screens and contract calls from `functional-spec.md`, the nine contracts from `contract-summary.md`, and the NFR-level decisions from `performance-design.md` and `security-design.md`.

## Deployment

| Facet | Choice | Rationale |
|---|---|---|
| Compute model | None server-side. One client binary (iOS + Android from a single Dart codebase), installed per device — `logical-components.md`'s single logical component | A `kind: ui` Unit runs on the user's device, not on AWS; there is no Lambda, container, or resolver to size. |
| Region | `ap-south-1` (Mumbai) — inherited from auth-unit's Infrastructure Design | Not a resource this Unit provisions; it is the region every backend endpoint the app calls lives in, so it is the region that governs the app's network latency budget (`performance-design.md`). |
| Networking topology | Outbound HTTPS only, from the device to: the shared AppSync GraphQL endpoint (Contracts 3-6, 9), the Cognito User Pool hosted UI + token endpoints (Contract 1/2), the Cognito Identity Pool (Contract 9's guest identity), S3 pre-signed URLs (Contract 6 download/upload), and Google's Firebase endpoints (Crashlytics upload, FCM token registration). No inbound surface; no VPC; no custom domain | TLS 1.2+ is enforced by every endpoint (`security-design.md` NFR4.1); the app makes no request outside these five destinations. The Cognito hosted-UI sign-in returns to the app through a **custom URL scheme** (`sarovarjinalaya://callback/` and `sarovarjinalaya://signout/`), declared in this Unit's `Info.plist` (`CFBundleURLSchemes`) and `AndroidManifest.xml` (intent-filter). The matching callback/sign-out URL entries on auth-unit's Cognito App Client are a **new requirement this Unit places on auth-unit** — auth-unit's approved Infrastructure Design covers only the Cognito→Google redirect URI, not the app-facing one — see Shared Infrastructure. |
| Storage strategy | None server-side. On-device only: Amplify Auth's default platform-secure session storage (iOS Keychain / Android EncryptedSharedPreferences) and the language-override preference in standard shared-preferences — `security-design.md`'s Data protection design | No custom persistence, no offline cache (`performance-design.md` NFR-PERF.3). |
| Environments | **Single-target build (Q1: B)**: every debug and release build of the app is pointed at the **production** Amplify backend (`production` branch), via a generated `lib/amplify_outputs.dart`. Local development uses `ampx sandbox`, whose own generated outputs file replaces it on the developer's machine. No build flavors; the staging backend (`main` branch, auto-deployed on merge — auth-unit's environment model) exists for backend-side verification only and is **never targeted by a device build** | The builder's explicit choice at this stage's interview. Consequence recorded openly: a backend change is exercised end-to-end from a real device only against `ampx sandbox` (pre-merge) and against production (post-promotion), never against staging. Acceptable for a solo builder shipping a first release; flavors can be introduced later without changing any backend resource. |
| Firebase environment | One Firebase project, ONE app registration per platform (Q2 resolved by Q5: A) — Android registered under the production application ID, iOS under the production bundle ID. Crashlytics collection is **disabled in debug builds** (`FirebaseCrashlytics.instance.setCrashlyticsCollectionEnabled(!kDebugMode)`), so local `ampx sandbox` development never reports into the production crash stream | Follows directly from the no-flavor decision: there is only one app identity per platform, so only one Firebase app per platform can exist. The debug-build switch is the one control that keeps developer crashes out of real users' data. |
| IaC approach | No `amplify/*/resource.ts` for this Unit. Its infrastructure is **configuration artifacts**: (1) `lib/amplify_outputs.dart` — generated, git-ignored, produced by `ampx generate outputs --branch production --app-id <amplify-app-id> --format dart --out-dir lib` for a release build and by `ampx sandbox --outputs-format dart --outputs-out-dir lib` for local development; (2) `android/app/google-services.json` and `ios/Runner/GoogleService-Info.plist` — committed (Firebase treats them as non-secret app configuration; the API key inside is restricted to the registered app IDs); (3) `android/key.properties` + the upload keystore — local-only, git-ignored (Q3: A); (4) the custom URL scheme entries in `Info.plist` / `AndroidManifest.xml` — committed source | Amplify Gen2's per-branch outputs file is the single source of truth for which backend a build talks to; the rest is platform config that belongs in the repository or on the builder's machine, never in an AWS resource. |
| Resource sizing | Not applicable — no server-side resource. Store-side size note: one Android App Bundle and one iOS archive per release; Play App Signing and Apple's distribution pipeline handle per-device delivery | Nothing to right-size; app-binary size is a Code Generation concern (asset trimming, `--split-debug-info`), not an infrastructure one. |

## Infrastructure Services

| Service | Role | Configuration | Notes |
|---|---|---|---|
| Firebase project (`sarovar-jinalaya`) | Crash reporting (Crashlytics, `security-design.md` NFR-CRASH.1) and push delivery (FCM, reminder-unit's Infrastructure Design) | One project. Two app registrations: Android (production application ID), iOS (production bundle ID). Crashlytics enabled on both; FCM enabled on both. Config files committed at `android/app/google-services.json` and `ios/Runner/GoogleService-Info.plist` | One console, one FCM service-account credential (owned and stored by reminder-unit in Secrets Manager). Debug builds do not send crash data (Deployment > Firebase environment). No Firebase Performance Monitoring, Analytics, or Remote Config is enabled — Crashlytics is the only Firebase product this Unit uses. |
| APNs authentication key (`.p8`) | iOS push-delivery credential FCM needs to relay to Apple | Generated once in the Apple Developer account (Certificates, Identifiers & Profiles > Keys, APNs enabled), uploaded once to the Firebase project's iOS app under Cloud Messaging settings. Never committed; never a GitHub Actions secret | Without it, reminder-unit's `deliver-push` reaches FCM but FCM cannot deliver to iOS devices — a silent first-run failure worth naming here. Android needs no equivalent (FCM delivers natively). |
| Google Play Console | Android store account and release channel | One app listing (production application ID). Play App Signing enrolled: Google holds the app-signing key; the builder holds only the **upload key** | Play App Signing means a lost upload key is recoverable through a Play Console key-reset request, whereas a lost self-managed signing key would orphan every installed copy — the safer default for a solo builder. |
| Android upload keystore + `android/key.properties` | Release-signing material for the App Bundle | Generated once on the builder's machine (`keytool -genkey`), referenced from `android/app/build.gradle` via `key.properties`; both files git-ignored; keystore password never in source | Q3: A — signing lives only on the builder's machine. A backup copy of the keystore belongs in the builder's own password manager / encrypted storage, not in the repository. |
| Apple Developer Program + App Store Connect | iOS store account, signing authority, TestFlight, release channel | Paid membership; one App ID (production bundle ID) with the Push Notifications capability enabled; Xcode **automatic signing** manages the Apple Distribution certificate and App Store provisioning profile on the builder's machine | Q3: A — no exported certificate/profile is stored anywhere but the builder's Xcode/Keychain. The Push Notifications capability on the App ID is what makes the APNs key usable for this app. |
| Cognito App Client (auth-unit's resource) — mobile callback configuration | Sign-in/sign-out redirect target for Amplify Auth's hosted-UI Google federation (Contract 1) | **Required, not yet provisioned:** callback URL `sarovarjinalaya://callback/` and sign-out URL `sarovarjinalaya://signout/` must be added to the `callbackUrls` / `logoutUrls` of the PUBLIC (no-secret) App Client auth-unit provisions, in every environment (sandbox, staging, production); the same scheme is declared in this Unit's `Info.plist` and `AndroidManifest.xml` | This is a requirement this Unit **imposes on auth-unit**: auth-unit's approved Infrastructure Design configures only the Cognito→Google redirect URI (`/oauth2/idpresponse`, registered in Google Cloud Console) and says nothing about the app-facing callback. The values belong in auth-unit's `amplify/auth/resource.ts` (`externalProviders.callbackUrls` / `logoutUrls`), so ownership stays auth-unit's and the change lands during auth-unit's Code Generation; this Unit owns the matching platform declarations. Without both halves, the first real sign-in fails with Cognito's `redirect_mismatch` error — the reason it is spelled out here instead of assumed. |
| Consumed backend endpoints (AppSync API, Cognito User Pool, Cognito Identity Pool, S3 via pre-signed URLs, reminder Lambdas) | The app's whole server side | Owned and configured by feed-unit, suggestion-unit, donation-unit, pdf-library-unit, reminder-unit, and auth-unit respectively; reached through the generated `lib/amplify_outputs.dart` | Not provisioned here. The `services/*.dart` layer is the only code that touches them (`security-design.md` NFR6.1; team.md Q12). |

## Shared Infrastructure

| Shared Resource | Owner Unit | Consumer Units | Access Boundary |
|---|---|---|---|
| Firebase project (Crashlytics + FCM) | flutter-app-unit (this Unit creates the project and registers the two apps) | reminder-unit (FCM push delivery via the Firebase service-account credential it stores in Secrets Manager) | This Unit owns the project, the app registrations, the committed config files, and the APNs key upload. reminder-unit owns only the service-account credential and the `deliver-push` Lambda that uses it; it never touches app registrations or Crashlytics settings. |
| Cognito App Client callback / sign-out URLs (custom URL scheme) | auth-unit | flutter-app-unit | **Open obligation on auth-unit** (raised by this Unit, not yet in auth-unit's approved Infrastructure Design): auth-unit adds `sarovarjinalaya://callback/` and `sarovarjinalaya://signout/` to its App Client's `callbackUrls` / `logoutUrls` in `amplify/auth/resource.ts` during its Code Generation; this Unit declares the identical scheme in its platform manifests. A change to either side must be made together (the project's "update both sides in the same change" contract rule, `contract-summary.md`). Auth-unit's Infrastructure Design is not amended here because its review is already closed; the obligation is carried forward explicitly instead of being assumed provisioned. |
| `lib/amplify_outputs.dart` (generated backend outputs) | The shared Amplify Gen2 app (every backend Unit contributes to what it contains) | flutter-app-unit | Read-only consumption; regenerated from the `production` branch before each release and from `ampx sandbox` during local development. Never hand-edited, never committed. |
| Cognito Identity Pool guest identity (Contract 9) | auth-unit provisions the pool; reminder-unit owns the guest-auth rules | flutter-app-unit | The app resolves the guest identity through Amplify Auth's unauthenticated path only (`performance-design.md`'s async startup step); no IAM credential is ever handled by app code. |

Nothing in this table is a resource this Unit owns and shares outward except the Firebase project — and even that is shared only as a delivery channel for reminder-unit, not as a data store.
